- PR merge convention in this repo = regular merge commit (`--merge --delete-branch`), matching `git log` history ("Merge pull request #NNN from ..."), not squash.
- **Sandbox stdout reliability quirk (important, cost real time this session):** commands run through the Bash tool in this environment can silently truncate stdout at unpredictable, inconsistent lengths for medium/large outputs -- observed with `gh pr view --json` (truncated ~120 bytes), and even `jq`/`grep -c`/`wc -l` piped output on the exact same file gave inconsistent counts (81 vs 51 vs 31) across repeated invocations of an otherwise-deterministic command. The underlying file written to disk was correct in every case (verified via the Read tool and via `stat -c%s`). **Workaround: for anything non-trivial, write output to a file with `>` and read it back with the Read tool, never trust `cat`/`grep`/`wc`/inline stdout from Bash for medium-to-large output.** GraphQL batch queries (aliasing `pullRequest(number: N)` per PR in one query) are the efficient way to pull mergeable-state for many PRs at once without dozens of separate `gh api` calls.
