## Defects and gaps (with repro)
1. **After a BOQ revision the dashboard's "% complete by BOQ value" drops to 0% (R-51).** Repro (fresh project AUDIT-1792415811169): import a BOQ with sub-tasks, log 3 Delta entries on sub-task 1.1 (60% of the parent: Report shows parent 60%, AED 3,000 earned), then `POST /api/scope/<id>/revisions` with the same codes. `GET /api/v1/projexa/dashboard/<project>` now returns `progressByBoqValuePct: 0` while `progressByActivityLogPct: 40`, and the screen reads "0% - Earned AED 0.00 of AED 9,000.00". Cause: earned value is matched on `boq_line_item_id` of the latest revision only (construction-reports-service.ts earnedValueReport ~l.836-863; construction-dashboard-service.ts resolveEarnedValue ~l.585 and the batched path ~l.1503), whereas the Work Progress screen re-matches superseded lines by item code. Not fixed (three code paths); recommended fix: fold progress rows from any revision onto the current revision's lines by item code (quantity summed, percent = latest by date). A pure helper with 6 passing tests was drafted for earnedValueReport only and deliberately not shipped as a half-fix. **FIXED, VERIFIED LIVE 2026-10-19 (compliance-tracker #2166, production 03fcb019):** on https://projexa-ai.com as the E2E Meridian test CEO, project AUDIT-1792415811169 now reads '% complete by BOQ value 37.78% - Earned AED 3,400.00 of AED 9,000.00' (API progressByBoqValuePct 37.78, earnedValue 3400, contractValue 9000, progressByActivityLogPct 40). 3,400 = the 3,000 logged on the superseded revision (60% of the 5,000 root) plus 400 from a later 10% entry on Ceiling paint (4,000); it was 0 before the fix.
