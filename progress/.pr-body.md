### What changed

`task-execution-engine.ts` combined three genuinely distinct
responsibilities in one file. Split into `src/lib/task-execution/`
(matching this codebase's existing convention of a dedicated subdirectory
for a large concern — see `ai-team/`, `engines/`, `gst/`, `ingest/`):

- **`dispatch-tools.ts`** — `dispatchTool()`, the read-only global-agent
  tool dispatcher. Re-exported from `task-execution-engine.ts` (not just
  imported) so the two existing external call sites
  (`src/app/api/v1/projexa/assistant/route.ts`,
  `src/lib/services/fde-service.ts`) keep importing from the same path
  unchanged.
- **`dispatch-engine.ts`** — `dispatchEngine()` + its pure helpers
  (`truthy`, `parseNumberList`), the computation-engine allowlist switch.
  Not re-exported — grep-verified nothing outside `task-execution-engine.ts`
  imported it before the split. `truthy`/`parseNumberList` are now exported
  (additive) with a new `dispatch-engine.test.ts` (13 tests) covering them —
  previously untested pure functions, matching this file family's existing
  pure-function-only test convention.
- **`task-execution-engine.ts`** itself — down to `executeTask()` and its
  orchestration helpers, now a single coherent responsibility.

No behavior change: every extracted line is a pure relocation, verified
byte-for-byte against the source ranges during extraction (see the progress
file for the full off-by-one/verification trail — this branch was 1326
commits behind `origin/main` when the split was first drafted, so it was
rebuilt fresh against current `main` content and merged for real before
this PR, rather than pushing stale code that would have silently reverted
recent upstream work).
