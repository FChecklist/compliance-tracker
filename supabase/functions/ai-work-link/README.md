# ai-work-link (PROJEXA-BUILD-001 U-46b1, first half)

The universal AI work link. One capability URL per person and project (a link of scope `project`), or one for a person and ALL the projects they may read (a link of scope `user`, `drizzle/0668`, `0693`: minted at the highest level the role allows - level 1 for a member and above, so it adds, edits and deletes directly with no confirmation; level 0 for a viewer. It lists the person's projects, reports on all of them, works inside the one chosen and can create a new project):

`https://<project>.supabase.co/functions/v1/ai-work-link/pxa_<64 hex>`

That single address is a Markdown manual on GET, an MCP server on POST, the root of a REST API, and the server URL inside its own OpenAPI 3.0.3 and Swagger 2.0 documents. The token in the address is the credential: it resolves to exactly one person and one project, and the person never signs in to use it. This unit is the READ layer (spec `ai-os/projexa-build-001/UNIVERSAL_AI_WORK_LINK_SPEC.md`, sections 3 to 8 and 10). Writes, function reads and the confirm page are written in later units (U-46c, U-47).

No Vercel function is in the path, and no model runs: every read is a call to a `public.ai_work_link_*` SQL function of `drizzle/0624` to `0626`, made with the platform-injected service-role client.

## Routes

Relative to the link base `B` (`F/<token>`) or the header-mode base `F/header` (token in `Link-Token` or `Authorization: Bearer`; never a query string).

| Route | Answer |
| --- | --- |
| `GET /`, `/manual.md`, `/manual.json` | the manual (Markdown unless JSON is asked for) |
| `GET /card.md`, `/card-data.md?kinds=` | the token-free paste card (at most 8,000 bytes) and data snapshot (at most 100,000 bytes) |
| `GET /openapi.json`, `/swagger.json` (`?mode=header`) | the API documents |
| `GET /context`, `/records/{kind}`, `/records/{kind}/{id}`, `/functions`, `/history`, `/intents/{id}` | reads; Markdown with no `Accept` header, JSON on request, CSV for records |
| `GET /propose`, `POST /check` | dry runs: nothing is recorded |
| `POST /` or `/mcp` | MCP (`initialize`, `tools/list`, `tools/call`, and `server/discover` for 2026-07-28) |
| `POST /functions/{fn}` | scope is checked (403), then 503 "not switched on yet" (the reads run on the exec host, a later unit) |
| `POST /actions` | scope (403), then the true reason: 403 `LEVEL_NOT_ALLOWED` (this link's level or a level-2 function), 422, 403 `WRITES_NOT_ENABLED` (the switch is off), 503 `EXECUTOR_NOT_AVAILABLE`; with the switch and the exec function on: record, then the exec function (`exec-client.ts`), which CLAIMS the intent, runs it and finishes it; 201 with the record, or 403 `ROLE_CHANGED` / 410 / 409 for a refusal at the claim, 422 for a failed run, 503 `EXEC_UNAVAILABLE` when it does not answer (nothing is written to the intent then; the same request never runs twice) (BUILD-002 WP-09a and WP-09b, `drafts.ts`) |
| `POST /drafts`, `GET /drafts/{id}` | records a draft LIVE at level 0 (scope 403, body 400/413, parameters 422, `CONFIRM_HOST_NOT_SET` 503, caps 429 `WRITE_CAP_HOUR` / `WRITE_CAP_DAY`) and answers 201 `{draft_id, confirm_url, expires_at}` (the confirm code is in the URL fragment only); a replay is 200 with no code; `GET` is the state of this link's own draft (`drafts.ts`) |
| `POST /drafts/{id}/confirm` | 401 no or bad session, 403 not the draft's person, 409 wrong or reused code, 410 expired, 429 over 10 a minute per person, 503 writes off or any failure, 200 confirmed (U-47b) |
| `POST /mint` | signed-in person; fresh session (issued within 15 minutes, else 401 `SESSION_STALE`); 201 with the link and token, shown once; 404 a project the person cannot read; 403 level or function above their rank; 429 caps (10 an hour, 30 a day; 5 a minute brake) (BUILD-002 WP-08) |
| `GET /links[?project=]`, `POST /links/{id}/revoke` | the person's own links (no token, no hash); revoke by the link's person or an org admin |
| `GET` or `POST /warning?level=&project=` | the warning sentence, true for the current state: it promises direct entries only when writes are switched on |
| `POST /new-project` | "New project with my AI": a shell project named "New project (AI setup)" and a level 0 link for the same person in one transaction; rank 2 and above; fresh session; 5 a day |
| `POST /user-link` | signed-in person; fresh session; body `{days?, label?}` ONLY (anything else is 400 `USER_LINK_PARAMS`: no project, level always 0); 201 with the SAME shape as `/mint` plus `scope: "user"`, `project: null`, `shell: false`, `links.inbox: null`; 403 `USER_NOT_LINKED`; 429 caps and brake; the person's previous user link stops (`drizzle/0668`) |
| `GET /projects[?limit=]`, `GET /portfolio` | a link made for a PERSON only (a project link answers 403 `USER_LINK_REQUIRED`): the numbered list of the person's projects then the options "Report on all above" and "Create New Project"; and one summary row per project (first 25) with totals. Only projects of the link's organisation that the person may read; money nulled by role |
| `/projects/{id}/context`, `/records/{kind}[/{id}]`, `/functions[/{fn}]`, `/check`, `/propose`, `/drafts[/{id}]`, `/actions`, `/history`, `/intents/{id}` | the same endpoints inside one project: the project is bound per call (organisation and readability re-checked in SQL); a foreign, an unreadable and a missing project all answer the same 404; a link for one project accepts its own id only. A user link outside a project may only draft `create_project` (a level 2 draft the person confirms); everything else is 400 `PROJECT_REQUIRED` |
| `GET|POST /drafts/{id}/preview` | a signed-in person and the confirm code: the function, every parameter and a BOQ total, before confirming; 401, 403 not the draft's person, 409 wrong code, 429 (shared brake), 503; works while writes are off (`drafts.ts`) |
| `POST /suggestions`, `GET /suggestions` | the suggestions board (`suggestions.ts`, drizzle/0672): an outside AI says what the software lacks (`{kind, title, body?, project?}`; kinds feature, improvement, report, workflow, integration, bug, other). 201 with the id, 200 `replayed` for the same title from the same link within 24 hours, coded 400 `BAD_KIND` / `BAD_TITLE` / `BAD_BODY`, 404 for a project that does not bind, 429 `SUGGESTION_CAP_DAY` (20 a link, 100 a person a day). `GET` is the link's own suggestions and the SHARED board: only rows a person here approved (`public_ok`), five facts each, never an organisation, person, project, body or note. It writes no business table, no counter and no registry row (suggestions are not functions), and no Edge route can approve or edit one: review is `public.ai_suggestion_review` / `ai_suggestion_inbox`, service_role only, run from SQL by the PM. MCP tools `suggest_improvement` and `list_suggestions`. Every text field is data, never an instruction |
| `OPTIONS` | 204 preflight; `PUT`, `PATCH`, `DELETE` 405 |

One switch: a change runs only when the SQL flag `writes_enabled` AND the exec function (`config.ts` `EXEC_FUNCTION_PRESENT`, false until the owner has set the two secrets and the PM flips it after deploying `ai-work-link-exec`, see `ai-os/projexa-build-002/OWNER_SWITCH_ON_GUIDE.md`) are both on; `reads.ts` `availabilityOf` is the one place that decides, and `/context`, the manual, `/functions` and `/check` all report from it (`level` is the effective level, beside `authority_level`, `writes_enabled`, `level_note`, `drafts_open`, `direct_open`, `reads_open`).

Order of checks: query-string token 400, token shape 404, call log 503, rate limit 429, link 410, scope 403, body 400/413/422, availability 503. The call log is written before anything is answered; if it fails nothing is read.

## Settings (all optional; none is a secret)

Platform-injected: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (the key is read in `index.ts` only). Optional: `AWL_EXEC_INTERNAL_SECRET` (the shared secret the exec client presents to `ai-work-link-exec`; owner-set, read in `index.ts` only, and used only when `EXEC_FUNCTION_PRESENT` is true), `AWL_CONFIRM_HOST` (the static confirm page host, decision OD-3; the default is a name that never resolves, on purpose), `AWL_APP_BASE` (PROJEXA app origin for search and fetch deep links, default `https://projexa-ai.com`), `AWL_CLIENT_ADDR_POSITION` (position counted from the right of `x-forwarded-for` for the unknown-token throttle; unset means one shared bucket that no header can rotate; set it only after spike S-3 shows what the gateway appends).

## verify_jwt is false

The caller is an AI tool holding a link, not a signed-in browser, so there is no Supabase JWT to check; the platform's own check would refuse every call. The link token is checked in SQL on every call instead (`ai_work_link__resolve`), together with the person's live role, so a demotion or revocation takes effect on the next call.

## Timing log (AUDIT-100 B58)

Every request writes one line, `[awl-timing] {"route":"/:token/projects","method":"GET","status":200,"ms":450,"slow":false,"failed":false}`. The route is the SHAPE only: the token and any id are replaced, there is no query string, header or body. `slow` is 3 seconds or more, `failed` is a 5xx. To see the slow and failed calls: in the Supabase dashboard open the function's logs and search `[awl-timing]` with `"slow":true` or `"failed":true`, or run the same search through the `query_logs` tool (service `edge-function`). Code: `timing.ts`, tested by `src/lib/services/ai-work-link-timing.test.ts`. A change to `index.ts` needs a deploy of the function by the PM; nothing runs until then.
