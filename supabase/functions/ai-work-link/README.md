# ai-work-link (PROJEXA-BUILD-001 U-46b1, first half)

The universal AI work link. One capability URL per person and project:

`https://<project>.supabase.co/functions/v1/ai-work-link/pxa_<64 hex>`

That single address is a Markdown manual on GET, an MCP server on POST, the root of a REST API, and the server URL inside its own OpenAPI 3.0.3 and Swagger 2.0 documents. The token in the address is the credential: it resolves to exactly one person and one project, and the person never signs in to use it. This unit is the READ layer (spec `ai-os/projexa-build-001/UNIVERSAL_AI_WORK_LINK_SPEC.md`, sections 3 to 8 and 10). Writes, function reads and the confirm page are written in later units (U-46c, U-47).

No Vercel function is in the path, and no model runs: every read is a call to a `public.ai_work_link_*` SQL function of `drizzle/0624` to `0626`, made with the platform-injected service-role client.

| File | What it is |
| --- | --- |

| `mcp.ts` | MCP, both protocol eras on one endpoint, no session. |
| `openapi.ts` | The OpenAPI 3.0.3 and Swagger 2.0 documents, cut from the same operation list as the router. |
| `config.ts` | The settings, one pure function of the environment. |
| `jwt.ts` | The JWT settings for the signed-in app routes of a later unit, and `VERIFY_JWT = false`. |

## Routes

Relative to the link base `B` (`F/<token>`) or the header-mode base `F/header` (token in `Link-Token` or `Authorization: Bearer`; never a query string).

| Route | Answer |
| --- | --- |
| `GET /`, `/manual.md`, `/manual.json` | the manual (Markdown unless JSON is asked for) |
| `GET /card.md`, `/card-data.md?kinds=` | the token-free paste card (at most 8,000 bytes) and data snapshot (at most 100,000 bytes) |
| `GET /openapi.json`, `/swagger.json` (`?mode=header`) | the API documents |
| `GET /context`, `/records/{kind}`, `/records/{kind}/{id}`, `/functions`, `/history`, `/intents/{id}` | reads; Markdown with no `Accept` header, JSON on request, CSV for records |
| `GET /propose`, `POST /check` | dry runs: nothing is recorded |
| `POST /` or `/mcp` | MCP (`initialize`, `tools/list`, `tools/call`, and `server/discover` for 2026-07-28) |
| `POST /functions/{fn}`, `POST /actions` | scope is checked (403), then 503 "not switched on yet" (no Edge executor) |
| `POST /drafts` | scope is checked (403), then 501 "written in a later unit" |
| `/mint`, `/links`, `/warning`, `/drafts/{id}/...` | 401 with no session, 501 with one (a later unit) |
| `OPTIONS` | 204 preflight; `PUT`, `PATCH`, `DELETE` 405 |

Order of checks: query-string token 400, token shape 404, call log 503, rate limit 429, link 410, scope 403, body 400/413/422, availability 503. The call log is written before anything is answered; if it fails nothing is read.

## Settings (all optional; none is a secret)

Platform-injected: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (the key is read in `index.ts` only). Optional: `AWL_CONFIRM_HOST` (the static confirm page host, decision OD-3; the default is a name that never resolves, on purpose), `AWL_APP_BASE` (PROJEXA app origin for search and fetch deep links, default `https://projexa-ai.com`), `AWL_CLIENT_ADDR_POSITION` (position counted from the right of `x-forwarded-for` for the unknown-token throttle; unset means one shared bucket that no header can rotate; set it only after spike S-3 shows what the gateway appends).

## verify_jwt is false

The caller is an AI tool holding a link, not a signed-in browser, so there is no Supabase JWT to check; the platform's own check would refuse every call. The link token is checked in SQL on every call instead (`ai_work_link__resolve`), together with the person's live role, so a demotion or revocation takes effect on the next call.

## How the PM deploys it

After the U-46a migrations (`drizzle/0621` to `0628`) are applied to production and the ACTIVE-CLAIMS entry for this function is on `main`: deploy the folder as the function `ai-work-link` with `verify_jwt` false, through the Supabase MCP or the CLI. The bundle needs `../_shared/ai-link/core.ts` and both generated JSON files beside the sources (whether the MCP file list accepts a `../_shared` path was not tried; the CLI bundles it). Then run the harness of `scripts/verify/ai-link/` against a test link (later unit U-46b2). Not deployed by this unit.
