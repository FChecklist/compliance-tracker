## Why (requirements R4, G5, R12: "complete database of that user AND THEIR ORGANISATION as per role")
The backend already serves 28 project kinds AND 9 organisation kinds (vendors, customers, companies, boq_categories, currencies, exchange_rates, departments, org_people, cost_visibility; sentinel project `__org__`, `org_kinds` and `org_view_class` in the manifest, `/pull` without a project, `/ids`, `/changes` with `project_id: "__org__"`), role-gated and column-redacted on the server. The laptop client engine consumes NONE of the organisation kinds yet, and it does not re-evaluate what it holds when the person's role, the organisation's cost-visibility setting, or the server's data epoch changes. Both gaps break "as per role".

## Do
1. **Organisation kinds in the replica** (`replica*.ts`, `sync-client*.ts`, `local-reader.ts`; FB has already changed `local-db` (schema 4) and the outbox, FA the identity/chunking, E6 the scheduler: read their code first and extend, do not rewrite): sync every kind the manifest lists in `org_kinds` under the project key `__org__` (project_scoped false): first pull (keyset, same cursor), exact-ids, id-inventory repair for deletes, the organisation change feed (`/changes` with `__org__`: updates and tombstones, only the kinds the role may read), signature verification exactly like project rows with the sentinel project, versions and dirty-row rules identical to project kinds. A role that may read no organisation kind (a viewer) gets none and the screens say so calmly. Cost: one more feed per sync round at most (use the backend's one-call `/heads` poll if it exists on the branch: read `handler.ts`), never a per-kind sweep when nothing changed.
2. **Readers for the screens**: `loadOrgLocal(kind, options)` beside `loadLocalFirst` (same tagged result: `not_synced` / `local`), role-filtered by what was synced; a small adapter per master used by the shell modules (suppliers/vendors for materials and procurement screens, departments and org people for assignment pickers, currencies/exchange rates for money display, cost-visibility config to hide cost fields exactly as the server does). Where a module cluster (`shell/modules/*`) already takes masters "through a small interface", implement that interface here and leave the module files alone (describe the one-line wiring in the report; the integrator does it).
3. **Role / class / epoch re-evaluation (server contract from D3, see README "view class", "epoch", "reset_required")**: the manifest's `view_class` and `org_view_class`, the sync epoch and a feed's `reset_required` must be remembered per project and compared on every sync: a different class means rows already on the laptop were redacted for another role: drop the affected kinds' rows for that project (never the outbox/dirty rows) and re-pull them; a kind or project the person may no longer read is removed from the laptop; a new epoch means every version and cursor is meaningless: full resync, dirty rows kept; `reset_required` for a project: resync that project. Every one of these is automatic and silent (R12), and none may lose a pending edit or draft.
4. **Peers**: organisation rows move between laptops only when `org_view_class` is equal; `org_people` is never peer-shared (see the README); make the peer layer honour it (the peer package already compares the project view class: extend the same check).
5. **Tests**: the conformance harness gains organisation scenarios against the REAL handler (first sync of masters for manager/member/viewer, an update and a delete reaching a laptop, role change from member to viewer dropping vendor rows while keeping a pending edit, cost-visibility change re-pulling money fields, epoch change, `reset_required`). Unit tests with `fake-indexeddb` for every rule. PLANT-bug proofs per the PREAMBLE's last section (use the allowed forms for isolation/role checks).
