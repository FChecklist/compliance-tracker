# Package lf-e12-lifecycle-e2e (laptop app, repo projexa): the life of the installed app, in a real browser

Read `lf-e9-COMMON.md` and `PREAMBLE.md`. Branch `claude/lf-e12-lifecycle-e2e` from `origin/main`.

## Requirements (owner)
V1 one versioned download (version number + date, every file numbered and versioned, recorded in Supabase); the app is not deleted by the browser until the person chooses; R9 the person is logged in until they sign out; sign-out and "two people on one laptop" never leak data (organisation isolation is non-negotiable); the user never has to think; cost near zero (a laptop's working day costs ~209 requests to our server, measured in a simulation). `docs/local-first/CONTRACT.md` (sections: release, 426 gate, identity, sign-out policy, "Default ON"), `PWA_OFFLINE.md`, `COST_MODEL.md`; code `src/lib/local-first/release/*`, `boot.ts`, `persistence.ts`, `identity.ts`, `sign-out*.ts`, `mode.ts`, `LocalFirstDefault`, `sync-client.ts`, `replica.ts`, `cost/*`.

## State
Only the four tests of `e2e/offline-local-first.spec.ts` ran in a real browser (R1, R2, R9, R10 at the simplest). Release UPDATES, the 426 gate, sign-out choices, opt-out, two people on one laptop, long-lived sessions and real cost counts have unit tests only.

## Do (each its own test in `e2e/lf-lifecycle-*.spec.ts`; stub in `e2e/support/lf-lifecycle-stub.ts`)
1. **Release update without data loss.** Install release N; seed an outbox edit and a draft; the stub then serves release N+1 (`/_release/release.json` with new file versions; your spec serves it through `page.route`, build two tiny releases with `scripts/make-release.mjs --root` fixtures as `projexa-live-release-probe.mjs` in compliance-tracker does): the laptop installs N+1 in the background, the app keeps running on N until the switch, the switch happens at a safe moment, the person's local rows, outbox and drafts are intact afterwards, the old release cache is cleaned up, per-file `file_no`/`file_version` and `px-release-<version>` caches match the manifest, the install is reported once (`/install`), a failed download (cut the network mid-bundle) leaves N working and retries later, a bundle whose sha256 does not match the manifest is refused.
2. **The 426 gate.** The stub answers `426 UPDATE_REQUIRED` (min_compatible above the laptop's release) on a route: the laptop stops sending anything except the release routes, shows ONE calm update prompt (not an error wall), keeps working locally, installs the newer release, and resumes; nothing typed is lost.
3. **Sign-out choices** (CONTRACT: keep-by-default). Sign out with the default: the local copy stays, a re-login is instant and works offline; "Sign out and delete this laptop's copy": copy removed, pending edits/drafts told to the person first and never silently destroyed; delete blocked by another tab holding the database: said in plain words; sign-out in one tab signs out the others.
4. **Two people on one laptop.** Person A (org 1) signs out, person B (org 2) signs in on the same browser: B never sees any of A's rows, drafts, outbox, cached project names, release pointer personId or AI surface; A signing back in gets A's copy; the flag opt-out (`px-local-first-off`) of one browser profile is respected for both and `setLocalFirstEnabled(false)` followed by a reload stays off.
5. **Logged in forever, deeper than R9.** Access token expired while OFFLINE for days (fake the clock): the app still opens and works; online with a refresh that fails for 5xx/429/captive-portal HTML never signs the person out; only a real "signed out" answer does; the durable identity mirror rebuilds a lost cookie.
6. **Storage eviction.** Delete IndexedDB (simulate the browser evicting it): the next online boot brings the data back with a calm "preparing" state, the outbox loss is detected and TOLD (if pending edits were in the deleted database that is a finding to report, not hide); delete only the release cache: put back silently; `navigator.storage.persist()` was requested once and its answer stored.
7. **Real cost count.** Script one working day in the browser with a fake clock where you can (open, sync rounds at the scheduler's cadence, 20 edits, three screen opens, sleep) while the stub COUNTS requests by route: assert the total stays within the budget in `src/lib/local-first/cost/cost-budget.test.ts` (measure and record the real number; the unit simulation says ~209), that `GET /heads` is the only call when nothing changed, that a first sync of P projects is paced (≤100 requests a minute), and that a circuit breaker stops a fan of doomed requests after a 5xx. If the real number is higher than the simulation, that is a finding: say by how much and why.
8. Console hygiene (as e10a) on every flow; the `currentTarget`/stale-closure bug class around any form you touch.

## Deliverables
`e2e/lf-lifecycle-*.spec.ts`, helpers, app fixes with tests, a short table of the measured cost numbers, and a list of anything the requirement says that the app does not do.
