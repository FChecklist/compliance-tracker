## Why
The outbox is the part of the app that holds the person's WORK while the laptop is offline. A review found that it can destroy it (a refused edit deletes the only copy of what the person typed), wedge it (a record deleted by someone else leaves an op retrying forever with no card; an op the server left `uncertain` never ends and is never shown), or send the wrong thing (a task save always includes `completionPercentage`, which the server refuses for derived-progress tasks, so the whole edit is rejected). The owner's rule is that the person never has to think and never loses work.

## Do
1. **Nothing the person typed is ever lost.** Keep every refused or abandoned op's content in a per-person `drafts` store (in the person's local database: bump the local DB schema carefully and migrate, see `local-db-v3.test.ts` for the pattern) until the person re-sends or discards it; `OutboxAttention` shows one calm card per draft: what was not saved and why (plain words from the task-error dictionary), with "Edit again" (reopens the form filled with their text) and "Discard". Sign-out must never delete a database that holds drafts or pending ops without saying so.
2. **Every op state ends and is visible**: the deleted-record conflict (`CONFLICT_WITHOUT_ROW`) becomes a first-class conflict kind with a plain card ("This was deleted by someone else. Keep my version as a new one / Discard"); `EXECUTION_UNCERTAIN` and a ledger row stuck `running` become a visible "checking" state with a bounded number of re-sends (the backend engineer is making the server resolve them by re-asking with the same `op_id` and base version: design the client to send the same op again and to treat `duplicate`/`conflict-by-effect` answers as "it is already in" ), never an eternal silent back-off; a whole-batch 403 (`NOT_LINKED`) pauses the outbox with one card instead of poisoning every op.
3. **R12 automatic merge ("the user does not have to think")**: when the server's row moved since the person's edit, do a field-level three-way merge (base = the version the edit was made on, mine = the edit, theirs = the server's current row, all from what the laptop already stores: `baseVersion`, the dirty row, the conflict's server row). Fields only one side changed merge silently and the op is re-sent against the new version; only a same-field disagreement becomes a conflict card, and then the default one-tap choices are "Keep mine" / "Keep theirs" (`keep_theirs` must restore the NEWEST server row, not the snapshot taken when the conflict was first seen: finding data:F8). Never merge a money or approval field on the laptop: those fields always go to the card.
4. **Send the right thing**: patches contain only fields the person changed (task save no longer always sends `completionPercentage`); `baseVersion` is captured when the form LOADS, not at save; the create ops send the `record_kind` hint the server needs (wire:F10, cost:COST-08) and stay under the per-op size ceiling with a clear message (wire:F12: 64 KB per op; 2,000 characters per text parameter); text longer than the limit is refused before it is queued, with the person's text kept; an applied event only reloads the form of the task it concerns (data:F5); non-retryable HTTP answers (400/403/413/404) are not retried forever (cost:COST-07).
5. **The dirty-row rule is enforced inside the database layer** (`local-db.ts`: `putRecords`/`deleteRecords` must refuse to overwrite or delete a row that has a pending op, no caller can forget it: data:F9) and `revertRow` handles a later pending edit of the same row correctly (data:F10). Ask for persistent storage before the first op is queued (reuse the PWA's `persistence.ts`; data:F13).
6. Tests: every behaviour above has a committed test that fails when it breaks (planted-bug proofs per the PREAMBLE: for the dirty-row guard and anything authorisation-like use the allowed alternatives, not an in-place edit of the check). Real-backend proof where possible through the conformance harness (when `CT_ROOT` is set). Update `outbox.test.ts` defaults tests (cost:TEST-13: the cost-bounding back-off defaults, not injected tiny values) and test the production wiring of `outbox-shared.ts` without stubbing it (cost:TEST-15).
