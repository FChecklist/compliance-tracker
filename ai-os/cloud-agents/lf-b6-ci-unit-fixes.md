## What happened
Package B3 added ONE switch for PROJEXA's own in-app model lanes (`src/lib/projexa-internal-ai.ts`, `projexaInternalAiEnabled()`, strictly `PROJEXA_INTERNAL_AI_ENABLED=1` turns it on; DEFAULT OFF = zero model cost, the owner's order) and gated every model call site. It also changed the wiring text of `supabase/functions/projexa-document-extract/index.ts` and `wiring.ts`. B3's own new tests pass, but the OLDER suites that exercise the model path were never run against the gate, so ~70 tests in about 10 files now fail (their model stand-in is refused because the switch is off by default, or a static source-text test no longer finds the wiring it asserts): `src/app/api/v1/projexa/projects/from-document/route.test.ts`, `route.job.test.ts`, `route.email-job.test.ts`, `src/lib/pipeline/chat-attachment.test.ts`, `src/lib/services/ways-reconcile.pglite.test.ts`, `src/app/api/v1/projexa/assistant/route.attachment.test.ts`, `src/lib/services/document-extraction-service.test.ts`, `projexa-document-extract.test.ts`, `projexa-document-extract-budget.test.ts`, `document-extraction-contract.test.ts` (reproduce each with `bun test --isolate <file>`, one at a time).

## Do
1. For every failing test decide what it MEANS and fix the TEST, never the gate: (a) a behavioural test whose subject is the extraction/assistant/reconciliation behaviour WITH the model path available must turn the switch ON for its own duration only (`process.env.PROJEXA_INTERNAL_AI_ENABLED = "1"` in a `beforeEach`, restored in `afterEach`/`afterAll`; or the existing test helper for it if B3 created one: read `src/lib/projexa-internal-ai*.test.ts`), and the same file (or B3's own tests) must still prove that with the switch OFF the path refuses calmly and makes no model call; (b) a static-source test (`index.ts wires the model only when ... a key`) asserts the wiring text: update the assertion to the new wiring (model only when the switch is on AND a key is set, always through the ledger-backed budget) and keep its intent.
2. NEVER weaken, delete or skip B3's guard tests (`projexa-internal-ai.architecture.test.ts`, `.transports.test.ts`, the `*-ai-off*` suites) or the gate itself; a call site of the model must stay behind the switch (the PREAMBLE's rule on security checks applies: prove a new test can fail with an injected wrong dependency or a throwaway mutant, not by editing the gate in place).

After the 10 files pass, run the WHOLE backend suite once, in the background, one process: `bun test --isolate src/ > /tmp/all.txt 2>&1` (about 7 minutes on this machine), and list every remaining failure. A failure that also exists on `origin/main` (check with `git stash`-free means: `git worktree`-less, i.e. run that single file on a clean checkout of main if needed) is pre-existing and goes in the report; any other failure is yours to fix. 4. Also run `node scripts/check-route-auth-guard.mjs`, `node scripts/check-service-header-comments.mjs`, and a restricted `tsc` over the files you changed.
