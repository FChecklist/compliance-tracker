## Rules specific to these packages
- **Never weaken what a test asserts.** No longer timeouts to hide a hang (lengthen only when a trace proves the app legitimately needs the time, and say so), no deleted assertion, no skipped test, no `retries`. Assert real VALUES (a quantity, a title, a role's visibility), not just that "something rendered".
- **Two kinds of failure, treated differently.** An APP bug: fix the app with a unit/component test that FAILS without the fix (planted-bug rule; for isolation/role/signature checks follow the PREAMBLE's classifier section, do not edit the security check in place). A STALE spec/stub: align it to the real shape from the real handler/contract.
- **Check for the BUG CLASS, not only the instance.** lf-e8's crash came from reading `e.currentTarget` inside a state updater; grep for the same pattern in your area. When you fix one, look for its siblings.
- **Every write the laptop can make must match the REAL registry.** The outbox sends `{function_id, params}` to the real pipeline (`ai-work-link-exec` runs `src/lib/pipeline/function-registry.ts` executors). A live push test just showed `update_task` needs `{projectId, issueId, title, ...}` (not `taskId`). For every write in your area, assert that the params the laptop builds use the parameter names the real registry/executor requires (read them in the compliance-tracker clone) and that the function id exists in `src/lib/local-first/ai/function-registry.json`.
- **No real network, no real secrets, no deploy.** Everything reaches only `localhost` and in-browser stubs. Nothing here touches Vercel, Supabase or any real account.
- **Vercel rate limit (important, learned today):** every push of a branch to GitHub creates a Vercel deployment (cancelled at once by `ignoreCommand`, but it still counts toward a per-day cap that is currently EXHAUSTED and is blocking the production deploy of the owner's app). The PREAMBLE says "push after every file group": for these packages COMMIT after every file group but PUSH at most FIVE times in total (after your first passing test, roughly every third commit, and at the end). The classifier-safety advice still applies: if a shell command is denied, push what you have at once and stop.
- Time budget: stop and report after about 2.5 hours or when your acceptance list is green twice, whichever is first.
