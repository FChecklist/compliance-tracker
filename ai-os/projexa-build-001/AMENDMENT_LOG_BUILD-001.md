## What this file is

Work order section 1 asks for one row per change this programme makes to WORK_ORDER_PROJEXA-BUILD-001 and to Addendum A. Each row below is one change. A row with no evidence is deleted, so every row carries a commit SHA, a file and line, a dated SQL result, an API response or a document reference. Where the same defect was reported by several verification agents the reports are merged into one row, and the source_ids column lists every agent amendment id (M-Axx-n from gaps_master.json) and every project manager decision id (PMD-nn from PM_DECISIONS.md) the row merges.

## Action meanings

- ADD: a new item, test or owner question the work order does not have.
- DELETE: a wording or figure removed from the work order.
- EDIT: an existing item, test or figure changed; the row gives the new wording or test.
- REJECT: an item, claim or wording that is wrong, already done or impossible; the row proves it. REJECT is welcome, and a REJECT row that has no test of its own points to the partner row that has one.

## How to read the boolean_test column

- Every command is one line, needs no keyboard input, and exits 0 for pass and non-zero for fail. A leading exclamation mark inverts a check that must find nothing.
- After the arrow, EXPECT gives the exact exit code or stdout. A value shown as printed on 2026-09-25 was run that day against the input files in the staging folder.
- Paths under ai-os/projexa-build-001/ are the repo copy of the plan (PMD-21). Commands that name a repository say which one to run them in. The sql-assert form is defined in REGISTER_CONVENTIONS.md (F1) and reads only.
- A file named in a test that does not exist yet is created by the item the row describes, and the row says so.
- No test deploys, unpauses, changes a Vercel setting or a DNS record, creates a Supabase branch, applies a migration or sends email. Tests that need a deployed instance are blocked_owner (PMD-11).
- Pipe characters are not used inside cells because the linter splits on them.
