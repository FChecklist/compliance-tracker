## Identity and browser-side reads
**PMD-01 (Q-ID1) Identity bridge = Edge Function gateway, spike first.**
Decision: browser-side reads of verdian-ai data go through a Supabase Edge Function on verdian-ai that (1) verifies the PROJEXA session JWT (ES256) against the projexa project's public key set, (2) resolves the person through compliance.users.auth_user_id, (3) queries as role app_runtime with the tenant setting applied, (4) returns keyset-paginated JSON. Rejected: (a) move the 114 PROJEXA users into verdian-ai (touches every login; 22 of 114 are not linked to compliance.users); PostgREST-direct with new RLS (role authenticated has no SELECT grant on construction tables, the tenant predicate reads the server-set setting app.current_org_id which PostgREST never sets, no function in the database references auth.uid()). Fallback (c): keep reads server-side and only move rendering to the browser, used if the key-set spike (register item U-25a) fails.
Evidence: LIVE_FACTS_D09_D10_D11_RLS.md section (d); IDENTITY_AND_EDGE_FINDINGS.md; A09 verifier claims, skeptic-confirmed.
Reversible: yes, until Phase 4 starts. Owner override: "use option (a)" or "use option (c)".

Evidence: GATE_2_8_FINDINGS.md sections 0, 1, 4; adapter.ts:120-141; adapter.test.ts:28,65; compliance.submissions 6 refusals of 7 measured.
Reversible: yes. Owner override: "enable openrouter for internal Level 1" (owner-only spend decision; not needed for anything else in this plan).
