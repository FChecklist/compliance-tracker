What is the same underneath, and what must change

One short page to go with Design A (Professional Firm) and Design B (Organisation). Design and estimate only: the live app and database were not changed.

The idea in two lines. A firm's client is just an organisation. So Design A is a layer of portfolio, team and branding over many Design B organisations; underneath, both run the same weekly cycle on the same data.

1 · The same underneath

PartWhat is shared
The weekly cycleIdentify, Classify, Prove: the same three stages, the same steps, the same count of steps (never a rating). Weeks run Monday to Sunday.
The register and classificationThe register of what is held (names of things only), and for each line whose data it is, basis, how long, children or not, and the derived flags.
Prove recordsEvidence fingerprints, breaches with the 72-hour and 6-hour clocks, requests and complaints with the 90-day ceiling, erasures, the signed-off week, the evidence pack.
HistoryThe append-only, hash-chained record of what happened and when. Both designs read and write the same chain.
People and viewsWhole-organisation members, and the rule that each person sees only what is theirs (including the clients they act for).
The Monday e-mailOne weekly block per organisation, built from the same function; a firm's version adds the person's own clients.
Two account types already existOnboarding, plans and billing already separate firm from institution (with company, school, NGO or other). A firm creates and owns client organisations, and each client is an ordinary organisation.

Flags and switches. ui_edition (derived from the existing account type, not stored), and per-screen switches: firm_portfolio, firm_bulk_actions, firm_signing, firm_branding, firm_engagements, org_units, org_parent_consent, org_grievance_page. A switch lets each screen ship dark and be turned on per account.

4 · Suggested order

  1. F0, then B1, B3, B7, B9: layout and wording only, using data and calls that exist; the organisation design becomes visible fast.
  2. A1, then A3 and A2: the portfolio, bulk actions and board give a firm the main reason to use the firm design.
  3. A4, A5, A6, A7, A8 in that order, as firms ask for them.
  4. B2, B5, B6, B8 next for organisations; B4 (parent consent) only after the owner's decision and a lawyer's review.
How sure are these numbers? They are my rough estimates for one developer, based on the existing code (the roll-up and "My clients" functions, the weekly screens, the breach and request calls, the parent page), not measured. Treat them as sizes, not promises. Nothing in this page was built.
